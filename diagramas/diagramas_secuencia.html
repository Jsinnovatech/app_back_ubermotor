🚀 Flujo completo de una carrera

Cliente pide → conductor acepta → llega → inicia → completa → califican

sequenceDiagram autonumber actor C as 👤 Cliente participant B as ⚙️ Backend participant W as ⚡ WebSocket actor D as 🛵 Conductor C->>B: POST /clientes/viajes (origen, destino, tarifa S/3+, yape/efectivo) B->>B: estado = solicitado B->>W: empuja viaje_nuevo (con id + rider) W-->>D: 🔔 Panel "Nueva carrera" (Aceptar/Rechazar, 15s) D->>B: POST /viajes/{id}/aceptar Note over B: valida: viaje en solicitado + sin otra carrera activa + saldo > 0 B->>B: estado = asignado, saldo -= 1 B-->>C: WS ubicacion → "Tu conductor está en camino" D->>B: PUT /conductores/ubicacion (cada 5s) B-->>C: 🔵 pin del conductor se mueve en vivo D->>B: POST /viajes/{id}/llegar B->>B: estado = llegado B-->>C: 🟡 "Tu conductor llegó, sube al moto" D->>B: POST /viajes/{id}/iniciar B->>B: estado = en_curso B-->>C: 🟢 "En viaje a tu destino" D->>B: POST /viajes/{id}/completar B->>B: estado = completado, viajes_completados += 1 B-->>C: ✅ "Llegaste, califica a tu conductor" C->>B: POST /calificaciones (1-5 ⭐) B->>B: rating_promedio del conductor se recalcula

💰 Saldo prepago diario

La plataforma gana con el prepago de carreras (0.40/carrera)

Compra de paquetes

sequenceDiagram autonumber actor D as 🛵 Conductor participant B as ⚙️ Backend D->>B: GET /recargas/paquetes B-->>D: 2 = 5 | 4 = 10 | 8 = 20 carreras D->>B: POST /recargas/comprar (paquete 4, yape) B->>B: recarga = pendiente D->>B: POST /recargas/{id}/confirmar B->>B: acreditar: saldo_fecha = hoy, saldo += carreras B-->>D: saldo = 10 carreras (solo HOY)

Consumo al aceptar

sequenceDiagram autonumber actor D as 🛵 Conductor participant B as ⚙️ Backend D->>B: POST /viajes/{id}/aceptar B->>B: ¿saldo > 0? (si 0 → "Sin saldo, recarga un paquete") B->>B: saldo -= 1 → 9 B-->>D: viaje asignado ✅
No acumulable: si saldo_fecha es de otro día, el saldo se reporta 0. El conductor recarga cada día que quiere trabajar.

⚠️ Escenarios tóxicos

Reglas de negocio para proteger a las partes

Cliente cancela → se devuelve el saldo

sequenceDiagram autonumber actor C as 👤 Cliente participant B as ⚙️ Backend actor D as 🛵 Conductor C->>B: POST /viajes/{id}/cancelar (quien = cliente) B->>B: estado = cancelado B->>B: si había conductor → saldo += 1 (se devuelve) B-->>D: carrera cancelada, saldo restaurado

Cada 3 rechazos → -1 saldo

sequenceDiagram autonumber actor D as 🛵 Conductor participant B as ⚙️ Backend loop 3 veces D->>B: POST /viajes/{id}/rechazar B->>B: registra rechazo, viaje vuelve a solicitado (para otro conductor) end B->>B: al 3er rechazo → saldo -= 1 B-->>D: ⚠️ "Has perdido 1 carrera por 3 rechazos"

Conductor con carrera activa no acepta otra

sequenceDiagram autonumber actor D as 🛵 Conductor participant B as ⚙️ Backend D->>B: POST /viajes/{id}/aceptar (mientras tiene asignado/llegado/en_curso) B->>B: detecta carrera activa B-->>D: ❌ "Ya tienes una carrera en curso, completa la actual"

Saldo 0 → no puede aceptar

sequenceDiagram autonumber actor D as 🛵 Conductor participant B as ⚙️ Backend D->>B: POST /viajes/{id}/aceptar B->>B: saldo = 0 B-->>D: ❌ "Sin saldo de carreras para hoy. Recarga un paquete"

🚨 SOS → Central de Policía

Doble toque del botón → alerta con todos los datos → webhook externo

sequenceDiagram autonumber actor U as 🛵 Conductor / 👤 Cliente participant B as ⚙️ Backend actor P as 👮 Policía/Serenazgo participant W as 🌐 Webhook externo U->>B: POST /sos (doble toque: lat, lng) B->>B: registra alerta (origen, foto, moto, seguro, contraparte, ubicación) B->>W: POST webhook (con Basic Auth usuario+clave) W-->>B: 200 OK loop cada 5s P->>B: GET /autoridades/alertas?estado=activa B-->>P: 🔴 alerta SOS activa con datos P->>B: GET /alertas/{id}/ubicacion-vivo B-->>P: 📍 moto moviéndose en el mapa (cada 3s) end P->>B: POST /sos/{id}/cerrar B->>B: estado = atendida
El webhook POLICIA_WEBHOOK_URL es el sistema externo de la policía. Si no está configurado, la alerta queda igual registrada en la BD y la ven los perfiles policía/serenazgo en la Central SOS.

⭐ Calificación mutua

Después de completar el viaje, ambos se califican 1-5

sequenceDiagram autonumber actor D as 🛵 Conductor participant B as ⚙️ Backend D->>B: viaje completado → botón "Calificar rider" D->>B: POST /calificaciones (viaje, 4 ⭐) B->>B: guarda + recalcula rating del cliente B-->>D: ✅ "Calificación registrada"

Ranking

sequenceDiagram autonumber actor U as 👤 Usuario participant B as ⚙️ Backend U->>B: GET /calificaciones/ranking?top=10 B->>B: ordena conductores por rating_promedio B-->>U: 🏆 top conductores con estrellas

🔑 Recuperación de contraseña

Código de 6 dígitos por email (Resend), vigencia 15 min

sequenceDiagram autonumber actor U as 👤 Usuario participant B as ⚙️ Backend participant E as ✉️ Resend U->>B: POST /auth/solicitar-reset (email) B->>B: genera código de 6 dígitos (15 min) B->>E: envía correo con el código E-->>U: 📧 "Tu código: 123456" U->>B: POST /auth/resetear-password (email, código, nueva pass) B->>B: valida código y vigencia B->>B: actualiza password_hash B-->>U: ✅ "Contraseña actualizada"

⚡ WebSockets (patrón InDrive)

Conexión abierta permanente: el backend empuja, no espera polling

sequenceDiagram autonumber actor D as 🛵 Conductor participant B as ⚙️ Backend D->>B: WS /ws/conductores?token=JWT B-->>D: conexión abierta (permanente) Note over B: llega una carrera nueva B-->>D: 🔔 {tipo: viaje_nuevo, id, rider} D->>B: aceptar/rechazar
sequenceDiagram autonumber actor C as 👤 Cliente participant B as ⚙️ Backend actor D as 🛵 Conductor C->>B: WS /ws/clientes?token=JWT B-->>C: conexión abierta (permanente) D->>B: PUT /conductores/ubicacion B-->>C: 📍 {tipo: ubicacion_conductor, lat, lng} Note over C: el pin de la moto se mueve en vivo
Fallback: si el WS se cae, el polling de 5s del front sigue funcionando. Los WebSocket se autentican con ?token= en la URL (Flutter web no envía headers de forma fiable).
